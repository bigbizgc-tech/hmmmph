# Blackout Syndicate 2.0 — Builder's Guide

The site is plain static HTML generated by `node build.mjs` (zero dependencies) into `docs/`.
Every page is one module in `src/pages/*.mjs`. The layout (`src/layout.mjs`) adds the head, top bar,
clearance HUD, "next file" teaser, footer, drawer and toasts. You only write the page's `<main>` content.

## Page module shape

```js
// src/pages/31-faq.mjs
import { BIZ } from '../data/business.mjs';
export default {
  path: 'faq.html',            // output path (subfolders allowed)
  file: 'File 14',             // set => this page is a "file" that earns clearance (visit + read)
  order: 31,                   // reading order in the clearance drawer
  navTitle: 'FAQ',             // short name used in drawer and next-file teaser
  section: 'faq',              // highlights the nav item: packages | how | work | about | faq | contact
  title: 'FAQ',                // <title> becomes "FAQ · Blackout Syndicate"
  description: '…',            // meta description, 140–160 chars, plain and specific
  teaser: '…',                 // one line shown (half redacted) on the previous page's "Next file" card
  next: 'about.html',          // which page the "Next file" card at the bottom points to (wide screens show
                               // that file's number huge on the right; files without a number get redaction bars)
  css: `…`,                    // optional page-only CSS (inlined in <head>)
  js: `…`,                     // optional page-only script (runs after site.js; window.BS is ready)
  jsonld: (ctx, config) => ({…}), // optional structured data
  noindex: true,               // optional
  body: (c) => `…html…`,       // the page content; `c` is the helper context below
};
```

Pages without `file` (thank-you, vault, privacy, terms, 404, washington) give no clearance for visiting.

A module may instead export a **function**: the build calls it with the merged config (`src/config.mjs` plus any
`BS_CONFIG_OVERRIDE`) and it returns a page, a list of pages, or `[]` to build nothing. Use it when the title,
description, teaser or JSON-LD depend on a switch (the package pages word their meta without prices when
`showPrices` is false; `washington.html` returns `[]` while `donateUrl` is empty). Never import `config.mjs` in a page.

## Helper context `c`

| Helper | What it does |
|---|---|
| `c.link('contact.html')` | Relative URL that works from any folder depth. **Always use it for internal links.** |
| `c.btn(text, href, variant)` | Button link. Variants: `''` gold, `'ghost'`, `'lg'`, `'sm'`, `'paper'` (for paper bands), combine with spaces: `'ghost lg'`. |
| `c.arrow` | Inline arrow SVG for buttons/links. |
| `c.classified({ id, level, title, body, bypass })` | Redacted paper dossier that opens at clearance `level` (1–5). `body` is HTML with `<p>`, `<ul><li>`, `<ol><li>`. Unique `id`. `bypass: true` adds "Break the seal anyway". |
| `c.mark('m1')` | One of the 3 hidden marks (+25 clearance). Ids `m1` (about), `m2` (how-it-works), `m3` (faq). Hide it somewhere discoverable but not obvious: inside a heading, next to a rule, at the end of a paragraph. |
| `c.offerCard(offer)` | The package "file" card. Its price spot follows `showPrices` on its own. |
| `c.crumbs([{t,p},…,{t}])` | Breadcrumbs. Last item has no `p`. |
| `c.contactLines()` | Big phone number (tap to call) with Call, Text (`sms:`) and Copy, then the email with Copy. The footer and the phone menu also carry Call and Text. |
| `c.socialRow()` | Social links with icons. |
| `c.icon('x')` | Brand icon SVG: x, tiktok, instagram, facebook, youtube, discord. |
| `c.config` | The merged build config (`src/config.mjs` plus any `BS_CONFIG_OVERRIDE`). Read switches such as `c.config.showPayLinks` from here, never by importing `config.mjs`. |
| `c.priced` | `true` unless `config.showPrices` is exactly `false`. Branch on it wherever a page prints a package price (see "Prices on or off" below). |
| `c.priceTag(o, cls)` | The price spot: `o.price` + `o.suffix` with prices on, `Ask us for pricing` in the same place and size with prices off. |
| `c.ASK` | The one wording for a hidden price: `{ label: 'Pricing', short: 'Ask us', line: 'Ask us for pricing', cta: 'Get pricing' }`. Never type these by hand. |
| `c.pricingHref(o)` | `contact.html?pkg=<slug>#intake`: where "Claim it" (prices on) or `c.ASK.cta` (prices off) sends people. The form opens with that package picked. |
| `c.classBtn(variant)` | The gold "<class price> · Book a class" button for Learn Claude With Me (price from `CLASSES`), to `learn-claude.html#book` (or `#book` on that page). Shows in both modes. |
| `c.washington`, `c.washingtonCard()`, `c.TRIP` | The Washington trip. `c.washington` is true only when `config.donateUrl` is set and `washington.html` was built; `c.washingtonCard()` is the small note card linking to it (empty string otherwise). `c.TRIP` holds the event, place, dates and what the money covers. |
| `c.BIZ`, `c.SOCIALS`, `c.LEVELS`, `c.POLICY` (refund/billing wording: use it verbatim), `c.PLATFORMS`, `c.REEL`, `c.OFFERS`, `c.BOOSTS`, `c.PLANS`, `c.ADDONS`, `c.SERVICES`, `c.offerPath(o)` | Data. Never hard-code a price: read it from the offer. |

## Prices on or off (`config.showPrices`)

The owner asked for no pricing on the site. `showPrices: false` in `src/config.mjs` hides every package price;
`true` brings every one back exactly as before. Nothing is deleted from the data: `src/data/offers.mjs`
(`price`, `suffix`, `oneMonth`, `regular`, and the amounts inside `spend`, `includes` and `faq`) stays the single source.

- **Read the switch** from `c.config` / `c.priced` in a page, or from the config a module function receives. Data helpers
  take that same object: `pricesOn(cfg)`, `offerFor(o, cfg)` (the offer with its `plain` wording swapped in when prices
  are off: `spend`, `includes`, `faq`, `summary`, `teaser`… with no amount), `plainOffer(o)` in `offers.mjs`, and
  `levelsFor(cfg)` in `business.mjs` (the clearance ladder: Level 2 reads "The field notes on every package file").
  Never print `price`, `suffix`, `oneMonth` or `regular` from a plain offer: they stay on it for sorting only.
- **Keep the prices-on markup as it is.** Branch with `c.priced ? <today's markup> : <plain markup>` so turning prices back on renders the same page.
- **With prices off, nowhere** shows a dollar amount: not in text, `<title>`, meta description, og/twitter tags, JSON-LD
  (no `Offer` price), aria-labels, data attributes, inline scripts or the X pixel `content_name` (the contact form's
  option text). No "from $X", no "/mo", no regular or struck prices, no launch-price talk, no one-month prices, no
  "how much of your money buys the ad" figures and no price comparisons ("three Blitzes cost about what Surge costs").
- **Where a price was**, say it one way: `c.priceTag(o)` or the `c.ASK` words ("Ask us for pricing"). The package action
  "Claim it" becomes `c.ASK.cta` ("Get pricing") to `c.pricingHref(o)`, next to Call and Text.
- **Keep** package names, what's included, run times ("one-time", "monthly", "month to month", "one month only, billed
  once") and `POLICY` wording verbatim.
- **Hide whole blocks whose point is the price** (price math, price ledgers and tables, comparisons, "plans from" strips)
  instead of leaving them empty: no empty box, no stray separator, and the copy around it must still read naturally.
  The math-* bonus files keep their id (the clearance ladder links there) and become field notes with no price.
- **FAQ answers** can carry `plain: { q?, a? }` (asked and answered without a price) or `priced: true` (only shown with
  prices on, such as "What does launch price mean?"). Counts and JSON-LD follow what is shown.
- **The contact form** lists package names only, and the note under the select shows the name and the file link.
  `thank-you.html` shows the package name only.
- **Two exceptions.** Learn Claude With Me keeps its class price in both modes (`CLASSES` in `offers.mjs`, `c.classBtn()`).
  The Washington donation page (`54-washington.mjs`) shows no dollar figure at all, and exists only while `config.donateUrl` is set.
- **Never invent**: no "affordable", "competitive", "cheap" or "starting low", and no new offers.
- **Check**: build with `showPrices` off and grep the output for `/\$\s?\d/`. The only hits are the class price.

## CSS components (in `src/assets/css/site.css`)

Tokens: `--void --coal --vault --smoke --ash --paper --ink --ink-mute --gold --gold-hi --brass --signal`;
fonts `--f-display` (Big Shoulders Display, uppercase headlines), `--f-body` (Archivo),
`--f-serif` (Bodoni Moda italic, the "whisper" accent), `--f-type` (Courier Prime, dossier labels).
Never introduce new colors or fonts. Use the tokens.
Only these cuts are loaded (`FONTS` in `src/layout.mjs`): Archivo 400 to 700 upright, Big Shoulders Display 800 and 900,
Bodoni Moda italic 500 and 700, Courier Prime 400 and 700. Ask for another weight or style and the browser fakes it, so stay
inside those. The stacks start with metric-matched fallbacks (`BSD Fallback`, `Archivo Fallback` in `site.css`) so the late
font swap doesn't move the layout; keep them first after the web font.

**Structure**
- `<section class="band">` → `<div class="wrap">`. Variants: `band--coal` (raised dark), `band--paper` (light dossier page, use 1 per page at most), `band--gold` (loud closing CTA, at most 1 per page), `band--tight`, `band--flush-top`.
- Inner page header: `<header class="pagehead"><div class="wrap pagehead__in">crumbs, .label, h1.h1, p.lede, .ctas</div></header>`
- `.band__head` (label + h2 + p) and `.band__head--row` (head left, link right).
- Grids: `.grid.grid--2|3|4`, `.split`, `.split--wide`. `.wrap--narrow` for reading width.

**Type**
- `.label` (typed uppercase eyebrow; `.label--dim`, `.label--red`), `.h1`, `.h2`, `.h3`, `.lede`, `.muted`, `.small`.
- Whisper accent inside a headline: `<h2 class="h2">Asked <span class="whisper">and answered.</span></h2>`. Use once per heading, not on every heading.
- `.prose` for long text (handles p, h2, h3, ul, ol, a, strong).

**Pieces**
- `.steps` ordered list (`<ol class="steps" style="--n:4"><li><h3>…</h3><p>…</p></li></ol>`). Only for a real sequence.
- `.ticks` / `.ticks--no` lists. `.ledger` (`<dl class="ledger"><div><dt>…</dt><dd>…</dd></div></dl>`).
- `.panel` (raised box), `.note` (dashed callout), `.badge.badge--red|gold`, `.stamp` / `.stamp--gold` (rotated rubber stamp).
- `.qa` FAQ: `<details class="qa"><summary>Question</summary><div><p>Answer</p></div></details>`.
- `.textlink` for "Read more →" style links (`<a class="textlink" href="…">Text ${c.arrow}</a>`).
- Forms: `.form`, `.form__row`, `.field` (label + input/select/textarea + `<p class="field__err" data-err-for="name"></p>`), `.chips/.chip`, `.form__alert`, `.hp` honeypot.
- Focus rings switch to ink on `band--paper` and `.classified`, and to void on `band--gold`. Anything else on a light or gold surface needs its own `:focus-visible { outline-color: … }`.
- A locked `.classified` body is clipped to about 11em and fades out, so long files don't become screens of black bars. Links inside a locked body leave the tab order.
- `.ctas` stack into one column of equal full-width buttons on phones (560px and below); a `.textlink` in the row keeps its own width.
- Add `class="rv"` to section-level blocks for a reveal on scroll (only fires for things below the fold). Optional `style="--d:.1s"` delay.
- `data-spot` on any element makes a gold searchlight follow the pointer (`--x/--y` set in px). Use for one hero-ish moment per page at most.

## Engine API (window.BS, available in page `js`)

- `BS.award(kind, id, amount, label)` — kind is `seen|read|mark|quiz|lead|blackout`. Use `BS.award('quiz', '', BS.XP.quiz, 'Package match found')`.
- `BS.track(name, params)` — X pixel event by config key (`lead`, `formSubmit`, `packageView`, `contactView`, `call`). An event whose ID is `''` in config does nothing. `call` is sent by the engine for every tap on a `tel:`, `sms:` or `mailto:` link (one listener for the whole page), so new phone, text or email links are tracked with no extra code.
- `BS.toast(main, sub, big, tone, href, note)`: feedback for the visitor. `tone` `'level'` is the gold one; with `href` the toast gets a small link label (`'#clearance'` opens the drawer). Toasts never take a tap or click meant for the page: the toast ignores the pointer and only its small link label can be tapped. On phones one toast shows at a time, compact, pinned under the top bar, for about 3 seconds, and a scroll sends it away; on desktop at most two show, top right under the clearance meter. Toasts wait (and anything on screen clears) while a lead form or an element marked `data-toast-quiet` (a page's big reveal, such as a quiz result) is on screen or any field has focus, while a classified sheet is declassifying, while the drawer or phone menu is open and while the lights are out; once the way is clear, level-ups and links show and small stale ones are dropped. One `BS.award()` makes one toast: a level-up, the third hidden mark or the Archive seal folds the clearance it paid into the same toast. Use toasts sparingly and never as the only place something is said.
- `BS.state()` (raw clearance record, read only), `BS.stamps()` (what the visitor has earned, for badges such as the Vault ID card: `{ level, xp, files, opened, read, archive, marks, allMarks, quiz, blackout, lead }`; listen for `bs:change` to redraw), `BS.level()`, `BS.open()` (opens clearance drawer), `BS.reduce` (reduced motion).
- Clearance is re-read from storage before every write, so several open tabs never wipe each other. Always change state through `BS.award()`, never by writing to `BS.state()`.
- Lead form: `<form class="form" data-lead novalidate>` with fields named `name` (required), `business`, `email` (required, type=email), `phone`, `interest` (select; each option `value="spark"` and `data-slug="spark"`), `platform`, `message`, plus honeypot `<input name="_honey" class="hp" tabindex="-1" autocomplete="off">`, `<div class="form__alert" data-form-alert hidden></div>`, and `<button class="btn btn--lg" type="submit">`. The engine handles validation, sending, pixel events and redirect to thank-you.html. `?pkg=slug` preselects.
- Thank-you: elements `[data-lead-name]`, `[data-lead-interest]`, `[data-lead-preview]` (hidden unless preview) are filled automatically.
  The `lead` conversion fires there only for a real send from that browser tab (a one-time token the form leaves in the tab must match `?sent=`), once per send, never on a reload or a direct visit.
- Classified sheets: the body is ruled paper, one rule per line of type and a blank ruled line between paragraphs, so keep bodies to `<p>`, `<ul>`/`<ol>` and `<strong>`. Locked text is typed in Courier; an opened sheet reads in the body face, and a bold lead-in at the very start of a paragraph or list item (`<strong>Do it today:</strong> …`) stays typewritten.

## Voice (non-negotiable)

- Plain, short, direct. Talks like a straight-shooting local guy. "We" for the business, "I" only inside founder quotes.
- **No invented facts**: no testimonials, client names, case studies, stats, follower counts, ratings, years in business beyond "ten years building things with my hands", awards, guarantees of results, office address, hours. If it isn't in `src/data/*.mjs`, don't claim it.
- Results line (use where you sell promotion): "Results depend on your content, your audience and the platform. No set number of views, likes or followers is guaranteed."
- No em-dash asides, no "not X, but Y" framing, no "worth noting", no emoji, no exclamation spam.
- Prices only from `src/data/offers.mjs`, and only while `showPrices` is on (the class price shows either way). See "Prices on or off".
- The syndicate/noir theme is flavor, not confusion: every heading must still say plainly what the section is about.
